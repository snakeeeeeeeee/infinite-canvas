# Canvas 模型静默同步设计

## 目标

已通过 Infinite Canvas 授权的 SuperToken 渠道默认每 5 分钟检查一次管理员配置的图片和视频分组模型。新增模型应自动进入画布、生图工作台和视频工作台，无需用户重新授权。

## 数据流

Canvas 使用已保存的图片 Module Key、视频 Module Key 和 Resource Key 调用 new-api 静默同步接口。new-api 必须确认三个 Key 属于同一用户，两个 Module Key 分别对应该用户 `CanvasGrant` 管理的图片和视频 Token，Resource Key 当前有效，并重新校验账号、管理员 Canvas 配置及目标分组权限。

校验通过后，new-api 在事务中复用现有 Token，只按当前分组可用模型更新分组和模型白名单，刷新 Token 缓存并返回图片与视频模型列表。同步过程不创建、删除、轮换或重新启用任何 Key；凭证被禁用、删除或过期时必须由用户显式重新授权。

Canvas 收到结果后更新同一 SuperToken 渠道的模型列表和 `syncedAt`，保留仍有效的当前模型；当前模型失效时沿用渠道配置现有的选模规则。所有工作区读取同一个 Zustand 配置，因此更新立即生效。

## 调度与失败

客户端初始化时检查 `syncedAt`，超过 5 分钟则立即同步；页面持续打开时使用五分钟兜底定时器。模块级请求锁避免同一标签并发，多标签通过持久化时间戳减少重复请求。页面隐藏时不主动同步，恢复可见后重新检查。

网络失败、配置停用、分组权限不足或凭证不匹配时保留原配置，不打断生成。显式凭证错误可以记录为下一次用户打开配置时可见的失败信息，但后台同步不循环弹出通知。

## 验收

- 管理员新增模型后，已有用户不重新授权也能在五分钟内获得新模型。
- 同步前后三个 Key 完全不变，Token ID 不变。
- 非 CanvasGrant Token、混用不同用户 Key、无效 Resource Key 均不能同步。
- 同步失败不移除旧模型，不修改当前选中模型。
- 多页面和多次渲染不会形成重复请求风暴。
