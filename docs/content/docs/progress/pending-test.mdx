# Pending Tests

The current release needs manual verification in these areas:

- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, image editing, drag-and-drop references, and generation configuration.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Settings import/export, Volcengine Ark protocol handling, and WebDAV-related configuration.
- Local source Docker Compose deployment should serve the frontend at host port 10001 while the container continues listening on port 3000.
- Provider empty state: new installs should have no built-in providers or default models; model selectors without a usable provider should open provider settings directly instead of showing an empty menu.
- SuperToken provider setup with fixed mainland/global regions, independent image/video Model API Keys, a shared Resource API Key, partial or full model refresh, and video choices limited to Kling, Seedance 2.0, and MiniMax H3. Either media capability should work without configuring the other.
- SuperToken provider editing should mark the shared Resource API Key as required, show a field error when it is empty, and keep Save disabled until a non-empty value is entered.
- SuperToken automatic authorization should return signed-out users to the centered consent page after login, fill and persist all three long-lived keys without exposing them in the callback URL, reuse existing Canvas-managed credentials on reauthorization, and leave the current provider unchanged after cancellation, popup failure, state mismatch, exchange failure, or missing group access. Manual advanced configuration must remain available.
- SuperToken Docker runtime origins: authorization and token exchange should use `SUPERTOKEN_AUTH_BASE_URL=https://supertoken.cc`, while mainland and global media requests retain `https://hk.supertoken.cc` and `https://api.supertoken.cc`; only an explicit `SUPERTOKEN_BASE_URL` should override both media API nodes, without rebuilding the Vite bundle.
- SuperToken image generation/edit and video frame/images/media modes across the image workbench, video workbench, and Canvas, including durable polling recovery, local stop behavior, protected result downloads, and local Blob persistence.
- SuperToken image batches: `gpt-image-2` and `adobe-gpt-image-2-count` should create one task with `output.count` up to 10 and restore every returned image to its original workbench slot or Canvas node; `gpt-image-2-count` and Gemini models should continue using independent single-image tasks. Retrying one failed result must generate only that result.
- SuperToken video requests with repeated Canvas node titles should assign stable `image-N`, `video-N`, and `audio-N` reference names without changing media order or upload filenames.
- Switching among Kling, Seedance, and MiniMax H3 should retain all reference media while applying the same model defaults in the video workbench and Canvas: Kling 3.0 uses start/end frames, Kling Omni and MiniMax H3 use image references, and Seedance uses mixed media. Resolution uses the lowest account-available SKU and duration uses the shortest supported value.
- Video reference entry points (upload, drag-and-drop, clipboard, and asset picker) should immediately enforce the selected model and reference-mode limits. Leonardo Seedance allows up to 4 images, 3 videos, and 1 audio file, with 7 visual references total; changing models must retain existing excess assets, mark the selection invalid, and block generation rather than deleting them.
- SuperToken browser media upload and real Adobe/Leonardo generation have been verified after enabling the deployed Canvas origins, `PUT`, and `Content-Type` in the target R2 bucket CORS policy.

The Chinese version contains the complete item-by-item acceptance checklist.
