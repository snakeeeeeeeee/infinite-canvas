# Pending Tests

The current release needs manual verification in these areas:

- Canvas navigation: the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should pan from either the background or a node. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; clicking the control should hide the floating toolbar and expand the slots upward and to the right. Every completed secondary image should keep a clearly legible primary-image action visible in both themes, and clicking the empty canvas should collapse the group.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: starting a resize while child images are expanded should collapse the group once, then resize the root node normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Settings import/export, Volcengine Ark protocol handling, and WebDAV-related configuration.
- Local source Docker Compose deployment should serve the frontend at host port 10001 while the container continues listening on port 3000.
- Provider empty state: new installs should have no built-in providers or default models; model selectors without a usable provider should open provider settings directly instead of showing an empty menu.
- SuperToken provider setup with fixed mainland/global regions, independent image/video Model API Keys, a shared Resource API Key, partial or full model refresh, and video choices limited to Kling, Seedance, and MiniMax H3. Either media capability should work without configuring the other.
- Video model picker: desktop should open below the trigger when space allows and flip above only on collision; Canvas nodes should use the compact 560px/420px layout while the workbench keeps the full layout, and narrow screens should use a bottom drawer. General and human-subject filters, Seedance/Kling/MiniMax families, concise capability details, Adobe/Leonardo provider cards, custom-model fallback, selection persistence, and all existing request parameters should remain correct.
- SuperToken provider editing should mark the shared Resource API Key as required, show a field error when it is empty, and keep Save disabled until a non-empty value is entered.
- SuperToken automatic authorization should return signed-out users to the centered consent page after login, fill and persist all three long-lived keys without exposing them in the callback URL, reuse existing Canvas-managed credentials on reauthorization, and leave the current provider unchanged after cancellation, popup failure, state mismatch, exchange failure, or missing group access. Manual advanced configuration must remain available.
- SuperToken Docker runtime origins: authorization and token exchange should use `SUPERTOKEN_AUTH_BASE_URL=https://supertoken.cc`, while mainland and global media requests retain `https://hk.supertoken.cc` and `https://api.supertoken.cc`; only an explicit `SUPERTOKEN_BASE_URL` should override both media API nodes, without rebuilding the Vite bundle.
- Canvas SuperToken routes: image/video nodes should inherit the provider default until explicitly switched between the accelerated and global routes; opening one desktop route popover should check both routes once, reuse the shared result for two minutes across nodes, show latency or a clear failure state, and keep existing tasks pinned to their creation endpoint. No background polling or automatic generation retry should occur.
- SuperToken image generation/edit and video frame/images/media modes across the image workbench, video workbench, and Canvas, including durable polling recovery, local stop behavior, protected result downloads, and local Blob persistence.
- SuperToken generation progress across the image workbench, video workbench, and Canvas image/video nodes: only known server progress should show a percentage, values must never move backward, unknown progress should use an indeterminate line, refresh recovery should retain the latest value, and native batches versus split tasks should update the correct result slots.
- Docker static caching after a fresh image build: `/`, `/index.html`, and `/config.js` should return `no-store`; missing `/assets/*.js` paths must return 404 instead of `index.html`; real hashed assets should return a one-year immutable cache policy. Purge the existing Cloudflare cache once before production verification.
- SuperToken image batches: `gpt-image-2` and `adobe-gpt-image-2-count` should create one task with `output.count` up to 10 and restore every returned image to its original workbench slot or Canvas node; `gpt-image-2-count` and Gemini models should continue using independent single-image tasks. Retrying one failed result must generate only that result.
- SuperToken video requests with repeated Canvas node titles should assign stable `image-N`, `video-N`, and `audio-N` reference names without changing media order or upload filenames.
- Leonardo Seedance 2.5 should expose only the returned 480p/720p SKUs, accept 4-30 second output, and offer both start/end-frame and mixed-media modes. Newly returned `adobe-seedance-*` and `leonardo-seedance-*` families should appear automatically without synthesizing unreturned resolutions.
- Adobe/Leonardo reference duration: Adobe video/audio may use a `15.001-15.300` second tail, while Leonardo video may use `10.001-10.300` and audio `15.001-15.300`; services normalize these to 9.9/14.9 seconds as applicable. Seedance 2.0/Fast video and audio each have a 15-second aggregate limit, while Seedance 2.5 video and audio each have a separate 30.2-second aggregate limit. Material overruns, normalization failures, and normalized durations over the model-specific aggregate limit must produce clear client errors. Images must not enter duration processing.
- Switching among Kling, Seedance, and MiniMax H3 should retain all reference media while applying the same model defaults in the video workbench and Canvas: Kling 3.0 uses start/end frames, Kling Omni and MiniMax H3 use image references, and Seedance uses mixed media. Resolution uses the lowest account-available SKU and duration uses the shortest supported value.
- Video reference entry points (upload, drag-and-drop, clipboard, and asset picker) should immediately enforce the selected model and reference-mode limits. Leonardo Seedance 2.0/Fast allows up to 4 images, 3 videos, and 1 audio file, with 7 visual references total. Seedance 2.5 media mode allows up to 30 images, 10 videos, and 10 audios (50 references total), requires visual media when audio is present, and keeps frame mode limited to 1-2 images. Changing models must retain existing excess assets, mark the selection invalid, and block generation rather than deleting them.
- SuperToken browser media upload and real Adobe/Leonardo generation have been verified after enabling the deployed Canvas origins, `PUT`, and `Content-Type` in the target R2 bucket CORS policy.
- SuperToken temporary reference uploads: repeating a video generation with the same local image/video/audio before the 30-minute expiry margin should reuse the completed URL; entering the margin or passing `expires_at` should upload again and persist the new URL. A synchronous missing/expired-reference response should force one re-upload and retry, while an asynchronous missing-reference failure should invalidate the cache so the existing Retry action uploads again. Refreshing the page must keep valid cache entries, and the permanent local Blob must remain the source of truth.
- Canvas generation failures: a failed SuperToken image task should show the original server `error.message` and a separate `code: <error.code>` line on the image node instead of only “All images failed to generate”. Long safety, validation, and upstream messages should wrap or scroll inside the fixed node without covering Retry; single-image, native batch, refresh recovery, and retry failures should preserve the same details.
- Canvas default image count: a fresh or incomplete configuration should create one image by default from new configuration nodes and direct node generation; explicitly selecting another count, including three, should continue to produce that count.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.
